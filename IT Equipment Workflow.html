3 สถานะ — ทำแล้ว vs ต้องทำต่อ

ทำแล้ว

  • หน้า DeviceSwap + AssetLogistics ต่อเข้า shell, Form IT, สิทธิ์ Admin/IT
  • Loop ครบ: ฟอร์มแจ้ง → คิว Dashboard → Stock Out → ตัดสต๊อก/ปิด ticket
  • ดึงทะเบียนจริง getAssetInventory() (319 เครื่อง) มาโชว์ Dashboard
  • สาขาจริง 226 จาก PC_BRANCH_MASTER
  • ฉลากส่ง KEX/Lalamove + ใบส่งภายใน (Office) + พิมพ์
  • ทุกฟอร์ม IT responsive (มือถือ/แท็บเล็ต/เดสก์ท็อป)
  • RD เคสสติ๊กเกอร์ v2 — recode / เปลี่ยนเครื่อง / ย้ายข้ามสาขา / ปิด · จัดกลุ่มตามผลต่อสติ๊กเกอร์
  • Shop Master ขับทะเบียน — drift rule CLOSED (ปิด→retire) + กัน NEW/SWAP สาขาปิด
  • เครื่องพิมพ์ (EPSON แคชเชียร์ / VPOS ครัว) ใน Shop Master + ดึงจากทะเบียนอัตโนมัติ
  • Reconcile Excel — เทียบทะเบียน↔Shop Master + Forecast Plan

ต้องทำต่อ (เมื่อกลับมา)

  • เพิ่ม backend จริง (Apps Script) แทน localStorage สำคัญ
  • Stock Out → เขียนกลับ store.assets (set shopCode/owner/status + ประวัติ device_rd_history)
  • Stock In → สร้างแถวเครื่องสำรองในทะเบียน (status=Available)
  • ส่งอีเมลแจ้งผล/HR + เลข Ticket จริง
  • Maintenance form ต่อ backend
  • ยืนยันแหล่งข้อมูล "แผนก (Department)" จริง (ตอนนี้ list ตั้งต้น)
  • i18n EN ของหน้าใหม่ (ถ้าต้องการ)

4 Data model — จุดเชื่อม backend

ของจริงอยู่แล้ว (mock-backend)

processInstallation() — CMPOS ติดตั้ง→ทะเบียน
getAssetDrift / applyAssetDrift — sync fleet
device_rd_history — ประวัติเปลี่ยนเครื่อง
PC_BRANCH_MASTER — สาขา 226 + hardware

mock ชั่วคราว (localStorage) — รอแทน

pc_asset_stock — คลังเครื่องสำรองพร้อมจ่าย (Stock In)
pc_asset_dispatch — ประวัติการจ่าย/จัดส่ง (Stock Out)
→ ตอนต่อ backend: map 3 ตัวนี้เข้า sheet/DB จริง แล้วให้ Stock Out เขียนลง store.assets + device_rd_history
หมายเหตุการต่อ backend: ฟังก์ชันฝั่งหน้าทั้งหมดเรียกผ่าน google.script.run.<fn> หรืออ่าน localStorage โดยตรง — จุดที่ต้องเปลี่ยนคือ alConfirmOut() / alStockInManual() / dsSubmit() ให้ยิงไป Apps Script จริง (เช่น processStockOut, processStockIn, processWebSubmit) ตามชื่อในโค้ดต้นฉบับที่ส่งมา · UX/UI คงเดิมได้
