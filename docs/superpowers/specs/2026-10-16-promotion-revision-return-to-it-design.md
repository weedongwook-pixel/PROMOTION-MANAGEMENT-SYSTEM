# แก้ไขโปรโมชั่นหลัง IT ดำเนินการ และส่งกลับให้ตรวจซ้ำ

## เป้าหมายที่ผู้ใช้ยืนยัน

ผู้ส่งเดิมเปิดฟอร์มแจ้งโปรโมชั่นพร้อมข้อมูลเดิมเพื่อแก้ไขได้ แม้ IT เคยทำเสร็จแล้ว ต้องระบุเหตุผล ส่งงานกลับ IT Settlement และให้ OP ตรวจใหม่หลัง IT ทำเสร็จ โดยไม่สร้างงานหรือจองรหัสซ้ำ

## สิทธิ์และขอบเขต

- บัญชีทั่วไปแก้เฉพาะแคมเปญที่ตัวเองส่ง ข้อยกเว้นบัญชีทดสอบ `mkt` / `MKT Team` คงเดิม
- ไม่เปลี่ยนระบบยืนยันตัวตนเดิมซึ่งอ้างอิงชื่อผู้ส่งในรอบนี้
- งานยกเลิกหรืองานที่ถูกลบไม่เปิดกลับผ่านฟอร์มแก้ไขนี้
- คงข้อจำกัดเดิม: ไม่เพิ่ม/ลบปุ่ม ไม่เปลี่ยนชื่อแคมเปญ ประเภท Online หรือไฟล์แนบผ่านขั้นตอนนี้
- เปลี่ยนเฉพาะรายการเดือนที่เลือก หากแคมเปญมีหลายเดือน เดือนอื่นคงเดิม

## ฟอร์มผู้ส่ง

- ใช้ฟอร์มเดิมทั้ง Item Set, Coupon, Bill Discount และ Voucher
- งานที่เคยผ่าน IT มีช่องบังคับ “เหตุผลและรายละเอียดที่แก้ไข” พร้อมข้อความแจ้งว่าจะส่งกลับให้ IT และ OP ตรวจใหม่
- Cloud เป็นผู้ตรวจว่าต้องระบุเหตุผล ไม่เชื่อสถานะที่เบราว์เซอร์ส่งมา
- งานที่ IT ยังไม่เคยทำไม่บังคับเหตุผล และไม่เปลี่ยนเป็นงานแก้ไขหลังขึ้นปุ่ม
- ปุ่ม “บันทึกการแก้ไข” / “ยกเลิกการแก้ไข” คงเดิม ออกโดยไม่เปลี่ยนข้อมูลไม่เตือน
- ไม่แสดงสำเร็จก่อน Cloud ยืนยัน receipt; หากส่งล้มเหลวคงข้อมูลที่กรอกไว้ให้ลองใหม่

## การบันทึกและประวัติ

- แก้รายการเดิมด้วย version guard, idempotency และ transaction เดียวกับประวัติการแก้ไข
- คง Promotion Code, Item Set Code, ผู้ส่งเดิม และวันที่ส่งเดิม ไม่แตะตัวนับ/การจองรหัส
- บันทึกผู้แก้ไข วันเวลา เหตุผล รายการช่องที่เปลี่ยน และข้อมูลก่อนแก้ของเดือนนั้นในประวัติ Cloud
- เก็บหลักฐาน IT/OP เดิมในประวัติก่อนตั้งสถานะรอบใหม่ ไม่ลบหลักฐานเก่า
- หาก IT ปิดงาน/มีผู้แก้ไขระหว่างเปิดฟอร์ม ให้ปฏิเสธข้อมูลเวอร์ชันเก่า ไม่เขียนทับอัตโนมัติ

## งานกลับ IT

- เฉพาะงานที่เคยผ่าน IT: เปลี่ยนสถานะปัจจุบันเป็น PENDING และประเภท EDITED
- การ์ด IT แสดง “รอ IT ดำเนินการแก้ไข” พร้อมผู้แก้ไข วันเวลา เหตุผล และสรุปจุดเปลี่ยน
- คงรหัสเดิมและไม่ให้กลไกจองรหัสใหม่ทำงานกับคิวแก้ไขนี้
- IT ตรวจแล้วกดบันทึกปิดงานผ่านขั้นตอนเดิม จากนั้นส่ง OP ตรวจรอบใหม่
- ไม่ทำให้การแก้ข้อมูลในเว็บถูกตีความว่าแก้บนเครื่อง POS จริงแล้ว

## OP และข้อมูลหน้าติดตาม

- ผล OP ของเวอร์ชันเดิมไม่ใช้ยืนยันข้อมูลที่แก้ใหม่
- หลังผู้ส่งบันทึก: สถานะปัจจุบันเป็น WAITING แต่ยังไม่ให้ OP ยืนยันก่อน IT ปิดงานรอบใหม่
- หลัง IT ปิดงาน: OP ตรวจข้อมูลใหม่ได้ และบันทึกวันตรวจรอบใหม่
- ศูนย์ติดตามและ Log แสดงผลบันทึก Cloud และสถานะงานรอบใหม่ตามจริง

## การตรวจรับ

1. งาน PENDING ที่ไม่เคยผ่าน IT ยังแก้ได้ตามเดิม
2. งาน COMPLETE/OP CONFIRMED เปิดฟอร์มได้ แต่บันทึกโดยไม่มีเหตุผลไม่ได้ทั้ง UI และ Cloud
3. บันทึกแล้วงานเดิมกลับ IT เห็นเหตุผล/ผู้แก้ไข/จุดเปลี่ยน รหัสและจำนวนแคมเปญไม่เพิ่ม
4. ประวัติก่อนแก้ยังอยู่ ส่งซ้ำด้วย editId เดิมไม่สร้างงานหรือประวัติซ้ำ
5. ผู้ใช้อื่นไม่มีสิทธิ์ยกเว้นบัญชีทดสอบที่อนุมัติ งานยกเลิก/ถูกลบยังถูกปฏิเสธ
6. IT ปิดงานใหม่แล้ว OP ตรวจซ้ำได้ และผล/วันที่เดิมไม่ถูกนำมาใช้แทนรอบใหม่
7. ทดสอบครบสี่ฟอร์ม พร้อมกรณี Cloud ล้มเหลว เวอร์ชันชนกัน และยกเลิกออกจากฟอร์ม

## สถานะ

เอกสารออกแบบสำหรับตรวจยืนยัน ยังไม่ได้แก้โค้ดหรือ deploy การเปลี่ยนขั้นตอนนี้
