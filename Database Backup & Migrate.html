2ดาวน์โหลดไฟล์สำรอง (ไว้ย้าย)

เก็บไฟล์เหล่านี้ไว้ = ย้ายไปฐานไหนก็ได้ · เลือกฟอร์แมตตามปลายทาง

3ย้ายเข้าฐานปลายทาง (Worker + D1 ใหม่)

ถ้าปลายทางเป็น Worker แบบเดียวกัน (โค้ด cloud/worker.js) — ดันข้อมูลเข้าตรง ๆ ผ่าน API

⚠️ ปลายทางต้องสร้างตาราง promo_store ไว้แล้ว (schema เดิม) · การดันข้อมูลจะ ทับ key ที่ชื่อซ้ำ ที่ปลายทาง

4ย้ายเข้า Java backend (Spring Boot)

หน้าตาเดิมทั้งหมด · Java เก็บข้อมูลอย่างเดียว — เอนด์พอินต์เหมือน Worker (/api/store) · โค้ดอยู่ที่ java-backend/

หลังย้ายเสร็จ: ใน index shell เปลี่ยนโหลด js/cloud-store.js → js/store-java.js (API ชื่อเดียวกัน หน้าอื่นไม่ต้องแก้) · แล้ว bump sw.js + ?v=

ฐานปลายทางที่รองรับ (schema เดียวกัน): Cloudflare D1 อื่น · SQLite · Postgres · MySQL · Supabase — ข้อมูลเป็น JSON blob ต่อ key จึงย้ายได้ครบ ไม่ตกหล่น · ถ้าต้องการ schema แบบ "แยกตารางจริง" (promotion_line/npd/vouchers …) แจ้งได้ ผมทำสคริปต์แปลงให้

📖คู่มือการย้ายข้อมูล (Migration Guide)

ทำตามลำดับ · เลือกเส้นทางตามปลายทางที่จะย้ายไป

ข้อมูลจริงอยู่ที่เดียว = ตาราง promo_store ในฐาน D1 (เก็บเป็น JSON blob ต่อ key) · หน้านี้เป็นแค่เครื่องมือดึง/ดัน ไม่ได้เก็บข้อมูลเอง

🅐 ย้ายไป Worker + D1 ใหม่ (ง่ายสุด · โครงเดิม)

  1. ที่ปลายทาง: สร้างฐาน D1 ใหม่ → รัน SQL สร้างตาราง promo_store (ดูข้อ "ย้ายด้วยมือ" ด้านบน)
  2. Deploy Worker ตัวใหม่ด้วยโค้ด cloud/worker.js → ผูก binding DB + ตั้ง secret SYNC_TOKEN
  3. กลับมาหน้านี้ → ข้อ 1 กด "เชื่อมต่อ + ดึงข้อมูล" (ต้นทาง)
  4. ข้อ 3 กรอก URL + Token ปลายทาง → กด "🚀 ดันข้อมูลทั้งหมดเข้าปลายทาง"
  5. เปลี่ยนระบบจริงให้ชี้ฐานใหม่: เปิดระบบ → ชิป ☁️ → ใส่ URL/Token ใหม่ → เชื่อมต่อ

🅑 ย้ายไปฐาน SQL อื่น (SQLite / Postgres / MySQL / Supabase)

  1. ข้อ 1 ดึงข้อมูล → ข้อ 2 กด ⬇ SQL dump (ได้ไฟล์ .sql)
  2. ที่ฐานปลายทาง รันไฟล์ .sql นั้น (มี CREATE TABLE + INSERT ครบ)
  3. ถ้าจะให้ระบบเดิมใช้ต่อ ต้องมี API ที่ปลายทางรูปแบบเดียวกับ worker.js (route /promo/store) — หรือปรับ endpoint ในระบบ
Postgres/MySQL: TEXT/INTEGER ใช้ได้เลย · MySQL เปลี่ยน ON CONFLICT เป็น ON DUPLICATE KEY UPDATE (ถ้า import ผ่าน tool ปกติไม่ต้องแก้)

🅒 เก็บสำรอง / กู้คืน (Backup & Restore)

  1. สำรอง: ข้อ 2 กด ⬇ JSON เต็ม เก็บไฟล์ไว้ (ควรทำสม่ำเสมอ)
  2. กู้คืน/ย้าย: ข้อ 3 กรอกปลายทาง → กด 📁 restore จากไฟล์ JSON → เลือกไฟล์ที่เก็บไว้
ก่อนย้ายจริงทุกครั้ง: กด ⬇ JSON เต็ม เก็บไฟล์สำรองไว้ก่อน · การดัน/restore จะ ทับ key ชื่อซ้ำที่ปลายทาง (ไม่ลบ key อื่นที่ปลายทางมีอยู่)

รูปแบบข้อมูล (อ้างอิง)

vJSON blob (ข้อมูลของ key นั้นทั้งก้อน)
updated_atepoch ms — เทียบว่าฝั่งไหนใหม่กว่า
อยากได้ปลายทางแบบ แยกตารางจริง (promotion_line, npd, vouchers … แยกกัน) แทน key/value — แจ้งได้ ผมทำสคริปต์แปลง JSON → SQL รายตารางให้ตรงกับ §0 ในหน้า Database Schema
